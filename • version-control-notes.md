# Git and Version Control Fundamentals

## 1. What Is Version Control?

Version control is a system that tracks and manages changes made to project files over time. It maintains a history of changes and allows developers to restore previous versions if something goes wrong.

It helps developers manage their code safely, track updates, and collaborate with team members.

## 2. Why Do Developers Use Git?

Developers use Git to track code changes, manage project history, and work collaboratively.

Git provides several benefits:
- Tracks changes in project files.
- Allows developers to restore previous versions.
- Supports branching and merging.
- Helps multiple developers work on the same project.
- Works locally without requiring a constant internet connection.

## 3. Common Problems Git Solves

Git helps solve several common development problems:

- **Code loss:** Developers can recover previously committed versions.
- **Confusing file versions:** Git maintains a history instead of requiring multiple manually named copies.
- **Collaboration problems:** Multiple developers can work on different branches.
- **Unexpected mistakes:** Developers can review changes and return to earlier versions.

## 4. Difference Between Git and GitHub

**Git:**
- A distributed version control software.
- Installed and used on a local computer.
- Tracks changes and manages project history.
- Supports branching and merging.

**GitHub:**
- An online platform for hosting Git repositories.
- Allows developers to share their projects.
- Supports collaboration through pull requests and issues.
- Provides online storage for repositories.

## 5. Centralized vs Distributed Version Control Systems

### Centralized Version Control System (CVCS)

In a centralized system, the project history is stored on a central server. Developers connect to this server to access and manage project versions.

Example: SVN (Subversion).

### Distributed Version Control System (DVCS)

In a distributed system, every developer has a complete copy of the repository, including its history, on their local computer.

Developers can work offline and synchronize their changes later.

Example: Git.

### Key Differences

| Centralized VCS | Distributed VCS |
| Uses a central server | Every developer has a complete repository |
| Depends heavily on the server | Supports local operations |
| Limited offline functionality | Supports offline work |
| Example: SVN | Example: Git |
